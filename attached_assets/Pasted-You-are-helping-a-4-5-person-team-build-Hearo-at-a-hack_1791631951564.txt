You are helping a 4-5 person team build "Hearo" at a hackathon (Education Technology track) in Replit. The attached README.md is the single source of truth for this project. Read all of it before doing anything.

## What we are building
A study tool that LISTENS instead of talking. A learner explains a topic out loud in their own words. The AI stays completely silent and checks each finished sentence against our reference material, live. A concept map fills in as they speak: green = covered correctly, red = said something wrong, amber = unverified, grey = not mentioned. When a claim is wrong, the node turns red within a few seconds and shows the correction plus the exact source line as proof. At the end, a session report shows the score, the gaps, the mistakes with corrections, and tomorrow's review question.

Hackathon scope: ONE polished topic (Earth's Seasons, unless the team decides otherwise in README section 13), working in Arabic and English.

## Architecture (follow README sections 2, 3 and 6)
- Browser (React + Tailwind + React Flow): live transcript, concept map, report modal, mic button, and a typed-text box.
- Voice service: WebSocket server, speech-to-text, sentence builder, session state, verdict rules, SQLite.
- AI service (FastAPI): POST /verify and POST /report, evidence check in code, topic pack loader.
- Key idea: the finished sentence is the narrow waist. Live mic, typed text, and recorded replay all become the same "final sentence" event.
- Verdict rules are plain code, not the model. The model proposes, the code decides. If the evidence quote does not appear in the cited source line, or confidence is low, the verdict becomes amber. Never label a claim confidently without evidence.
- Frontend is ONE reducer that turns the event stream into screen state, so recordings can be replayed with the same events.
- Not building: vector DB, accounts/login, text-to-speech, agent frameworks, fine-tuned models, user-uploaded material, mobile.
