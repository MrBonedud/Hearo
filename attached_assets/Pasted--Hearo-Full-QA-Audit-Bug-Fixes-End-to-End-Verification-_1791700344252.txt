## 3. Complete Arabic/English localization and RTL QA

The previous report explicitly stated that a working Arabic/English language switcher had not been implemented. Do not treat RTL support alone as completed localization.

Audit the existing implementation and finish any missing requirements.

### Language infrastructure

- Support Arabic and English throughout the implemented interface.
- Use Arabic as the default for a first-time visitor unless a valid saved preference exists.
- Detect the browser language on the first visit: English browsers may default to English; Arabic or unsupported browser languages should default to Arabic.
- A saved user selection must take priority over browser detection.
- Persist the selected language using `hearo.lang` in `localStorage`.
- Update `<html lang>` and `<html dir>` immediately when the language changes.
- Update the document title and meta description to match the selected language.
- Avoid a full-page reload where the current architecture permits live switching.
- Handle invalid or missing stored values safely.

Use the lightweight localization architecture specified for this project. Do not install a heavy localization library merely to implement these requirements.

### Translation coverage

Inspect every implemented screen and translate all user-facing text, including:

- Navigation and shared controls.
- Landing-page content and calls to action.
- Study-session instructions and recording states.
- File-upload messages and validation errors.
- Assessment feedback and reference labels.
- Concept-map labels and reports.
- Empty states, confirmations, notifications, and error messages.
- Tooltips, placeholders, accessibility labels, and dynamic status text.

Use natural, concise Jordanian Arabic for user-facing Arabic copy, consistent with the existing product tone. Avoid literal translations and preserve familiar technical terms when appropriate.

Keep `Hearo` as the product name.

Do not translate user-generated content or technical identifiers indiscriminately.

### RTL and LTR correctness

Inspect actual component behavior in both directions.

- Sidebar placement and navigation order.
- Top-bar alignment and profile controls.
- Form fields, buttons, cards, dialogs, and dropdowns.
- Directional icons versus non-directional icons.
- Concept-map labels, connections, and scrolling.
- Mixed Arabic/English text and user-generated quotations.
- Text wrapping, alignment, spacing, and responsive overflow.

Use logical CSS properties where appropriate. Do not blindly flip all icons or replace every physical positioning property without inspecting its purpose.

Use `dir="auto"` for user-generated text when appropriate.

### Language-switching regression tests

Verify:

1. First-visit language selection.
2. Switching Arabic to English.
3. Switching English to Arabic.
4. Persistence after refreshing the page.
5. Correct behavior when `localStorage` contains an invalid value.
6. Correct document direction, language, and metadata.
7. Complete translation coverage across the implemented screens.

If some of these requirements are already implemented correctly, preserve them and test them instead of unnecessarily rewriting them.
