## 4. Localization infrastructure

Create a lightweight localization structure under `src/i18n/`, adapting paths if the existing project uses a different source directory:

- `translations.ts` — all user-facing English and Arabic translations.
- `LanguageContext.tsx` — language provider, language state, and switching logic.
- `useTranslation.ts` — a reusable `t(key)` hook.
- Add a small utility for pluralization and localized date formatting if needed.

Use TypeScript types for supported languages and translation keys. Keep translation keys consistent across both languages.

Requirements:

- Supported languages: `ar` and `en`.
- Default language: Arabic.
- On the first visit, inspect `navigator.language`. If the browser language is English, use English; otherwise default to Arabic.
- Once a user has selected a language, their saved preference must take priority over browser detection.
- Persist the selection in `localStorage` using `hearo.lang`.
- Handle missing or invalid saved values safely.
- Avoid hydration mismatches, initialization flicker, and unnecessary re-renders.
- Integrate the provider at the appropriate application root without disrupting existing providers or routing.
- Avoid duplicating translation state across components.

The translation function must support all actual strings used by the interface, including interpolation where necessary. Do not leave scattered hardcoded UI text outside the translation system.

Do not translate API payloads, database values, identifiers, or internal technical values unless they are explicitly intended for display.

## 6. Document language, direction, and metadata

- Arabic: `<html lang="ar" dir="rtl">`

Update `index.html` where appropriate, but ensure the runtime language switch also updates the document attributes and metadata.

### CSS requirements

- Prefer logical CSS properties over physical left/right properties.
- Use `margin-inline-start`, `margin-inline-end`, `padding-inline-start`, `padding-inline-end`, `inset-inline-start`, and `inset-inline-end` where appropriate.
- Use `text-align: start` or `end` where appropriate.
- Avoid broad RTL overrides that accidentally break individual components.
- Preserve intentional physical positioning for elements that must not mirror.
- Do not blindly replace every occurrence of `left` and `right`; inspect the purpose of each rule first.

Use targeted `[dir="rtl"]` selectors only where needed. Keep the existing responsive behavior intact.
