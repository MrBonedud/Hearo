## 1. CRITICAL: Fix the scrolling behavior across the entire application

There is a noticeable frontend scrolling problem: when I scroll, the behavior is inconsistent between different parts of the interface. One area scrolls, while another area or the surrounding page behaves differently.

This is especially noticeable on the guided sample page:

- Page/section: Large-Scale Web Applications
- The page contains a concept map, six concepts, reference excerpts, a sample progress indicator, and a footer.
- The page currently feels as though its scrolling behavior is not properly coordinated.

**Do not assume the cause. Inspect the actual implementation and identify the root cause before changing the layout.**

Investigate all relevant possibilities, including:

- Nested scroll containers.
- Multiple elements using `overflow-y: auto`, `overflow-y: scroll`, or `overflow: hidden`.
- Fixed or sticky elements interfering with normal document scrolling.
- Incorrect `height`, `min-height`, `max-height`, and `100vh` / `100dvh` combinations.
- Containers with fixed heights that cut off content.
- Flexbox or grid children that cannot shrink because `min-height: auto` is applied.
- Incorrect `position: fixed` or `position: sticky` behavior.
- Scrollbar behavior and layout shifts.
- Scroll chaining and overscroll behavior.
- Horizontal overflow affecting the page layout.
- Event handlers that intercept or prevent normal scrolling.
- Modals, drawers, or overlays that leave the document scroll locked.
- Layout changes caused by conditional rendering, navigation, or changing content.
- Responsive CSS rules that create different scrolling behavior at different breakpoints.

### Required scrolling outcome

Establish a clear, consistent scrolling model.

1. The main document should scroll naturally when the page content exceeds the viewport.
2. Independent internal scrolling should only exist when it is intentional and genuinely improves usability.
3. Users should not have to guess whether they need to scroll the page, a card, a panel, or another nested area.
4. Scrolling over ordinary content should not unexpectedly move a different section.
5. No content should become inaccessible because of a fixed height, hidden overflow, or a nested scroll container.
6. The page must not become trapped in an internal scroll area.
7. Scrolling should work consistently with a mouse wheel, trackpad, touch gestures, and keyboard navigation.
8. Sticky elements, if present, must not cover content or make the interface feel broken.
9. The footer and final content must remain reachable.
10. Avoid unnecessary nested scrollbars.

**Important:** Do not blindly remove every `overflow` property or force every container to `overflow: visible`. Some components may legitimately require internal scrolling. Make a deliberate decision for each container based on its role.

Inspect the global layout, shared page shell, navigation, main content wrappers, and the specific guided sample page. Fix the underlying shared cause wherever possible instead of applying isolated CSS patches.
